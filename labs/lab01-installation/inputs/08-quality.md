# Atributos de Calidad

## Introducción

Este documento describe las características de calidad que deberá cumplir el sistema.

Estos atributos tendrán prioridad sobre decisiones concretas de implementación.

---

# Mantenibilidad

El sistema deberá ser sencillo de mantener.

La incorporación de nuevos módulos no deberá requerir modificar componentes existentes.

La estructura del proyecto deberá facilitar la evolución del sistema.

---

# Reutilización

Las funcionalidades comunes deberán implementarse una única vez.

Todo componente reutilizable deberá trasladarse a las bibliotecas comunes.

---

# Legibilidad

El código deberá ser fácilmente comprensible.

La claridad tendrá prioridad sobre optimizaciones prematuras.

---

# Modularidad

Cada módulo deberá implementar una única responsabilidad.

Los módulos deberán poder desarrollarse y evolucionar de forma independiente.

---

# Robustez

El sistema deberá detectar errores de forma temprana.

Los mensajes deberán facilitar el diagnóstico y la resolución de incidencias.

---

# Consistencia

Todos los módulos deberán seguir las mismas convenciones.

La experiencia de utilización deberá ser homogénea.

---

# Reproducibilidad

Dos instalaciones equivalentes deberán producir el mismo resultado.

Las diferencias entre sistemas deberán minimizarse.

---

# Escalabilidad

La incorporación de nuevos módulos no deberá aumentar significativamente la complejidad del sistema.

---

# Extensibilidad

La arquitectura deberá facilitar la incorporación de nuevas herramientas.

Las ampliaciones deberán requerir un impacto mínimo sobre el sistema existente.

---

# Observabilidad

El sistema deberá proporcionar información suficiente para comprender su funcionamiento.

Todas las operaciones importantes deberán quedar registradas.

---

# Testabilidad

Cada módulo deberá poder verificarse de forma independiente.

La validación del sistema completo deberá componerse a partir de verificaciones individuales.

---

# Simplicidad

La complejidad deberá permanecer oculta tras interfaces sencillas.

El usuario no deberá conocer los detalles internos del sistema para utilizarlo.

---

# Documentación

Toda funcionalidad relevante deberá encontrarse documentada.

La documentación formará parte del propio sistema y evolucionará junto con él.

---

# Automatización

La automatización deberá reducir el trabajo repetitivo sin ocultar el funcionamiento del sistema.

El conocimiento siempre tendrá prioridad sobre la automatización.
